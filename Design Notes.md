# Design Notes — Production Workflow

Running log of design decisions for the title/escrow production workflow: Order Entry through Search/Exam/Schedule A. See also [[Design Notes - Platform]] (system capabilities) and [[Design Notes - Curative & Tasking]] (Curative/CTC, Tasking, Order Contacts, MCP research) — read all three together. Anything still open goes to [[Open Items & Parking Lot]]. The actual coded prototype (Genesis) and its live link are tracked in [[Genesis Build Log]].

## Overview & philosophy

- Building new title/escrow production software combining the best of SoftPro Select, Qualia, and ResWare. No coding experience going in; built via AI-assisted ("vibe coded") development. Started with a roadmap/narrative doc — see [[Title & Escrow Platform Roadmap]].
- Core architecture: single-source-of-truth / field-level ownership — each fact is keyed once at its authoritative stage and flows downstream. Documents are generated OUTPUTS of canonical data via templates, never the source of truth.
- Unanswered questions get logged to [[Open Items & Parking Lot]] in real time.
- Reporting: Tableau-style drill-down, data warehoused separately from the production DB, cadence Daily/Weekly/Monthly/Quarterly. Live order-pipeline visibility; turn-time reporting monthly, sourced from timestamped Tasks. Saving a concrete artifact into the file both completes its task and advances status in the same event.
- Staff assignment: POD (fixed team by geography), Round Robin (within POD), Manual override. Working roles aren't licensing-constrained; Licensee of record is separate (usually upper management, "when applicable"). Licensee reviews are checklist tasks: Licensed Title Review (Typing/Exam), Licensed CD Review (Closing), Licensed Policy Review (Policy).
- Task taxonomy: Checklist tasks (granular, role-internal, may waterfall) vs. Milestone tasks (few, file-level, fixed external anchors, feed turn-time reporting). Due dates anchor per task type (e.g. Curative anchors to pipeline-entry date, not Order Received Date).
- Milestone list, in order: Order Entry, Search, Typing and Exam, Curative, Closing, Post Closing, Funding, Recording, Policy and Remittance.
- **Principle:** hard separation between "my workflow" (M&L's specific process) and the software's capabilities — any agency can build its own workflow/triggers on top of platform capabilities. Three tiers: (1) fixed core, not agency-configurable — the fixes for known industry pain points: no-delete/disposition pattern, Draft/Final edit-lock, Register auto-population from the Master Settlement Statement, commingling-prevention on batch disbursements; (2) out-of-the-box defaults; (3) agency-configurable via the workflow builder. Full detail in [[Design Notes - Platform]].

## Prototype UI shell

- Layout: order-list sidebar (navy, far left) → vertical File Sections nav (Order Entry, Contacts, Property, Prelim Search, Commitment — the primary workflow sequence) as its own column → main content, with a horizontal toolbar (Requested Tasks, Checklist Tasks, Attachments, File History) sitting above the content panel, below the order header. Both navs write to the same tab-state and share rendering, but are deliberately separate: vertical stack = the core file-building sequence, horizontal toolbar = order-level utilities available regardless of which section you're in.
- Requested Tasks (toolbar): Requested Date, Requested Due Date, Due Date, Received Date, Notes, seed chips for common types (Search Package, Date Down, Payoff, Estoppel, Municipal Lien Search, Tax Cert), explicit Status field (Required/Requested/Received/N/A/blank) as an inline colored pill-select. Moving Status to Received auto-stamps Received Date if not already set. Not yet wired to the broader task/milestone-trigger system — pure manual log for now.
- Checklist Tasks (toolbar): Description, Milestone (the 9-item list), Due Date, explicit Status field (Required/Completed/N/A/blank) as an inline colored pill-select. Moving Status to Completed auto-stamps Completed Date. Not yet role-scoped or waterfall-aware — flat list per file for now.
- Order Information screen is the 2nd vertical File Section (right after Order Entry): Order Received Date, Order/Title/Escrow Status with the documented value lists, Functional Role assignments (free-text name fields for now). Title Status's "Typing and Exam" value was renamed to "Exam" to match the documented status list.
- Attachments (toolbar) — this is the digital file, holding versions of the Commitment, CD, and other generated docs, NOT a physical-document log. Platform constraint: Genesis runs as a published Claude Artifact, so there's no arbitrary end-user file-upload sync across devices. Only documents Genesis itself generates get captured, stored as plain HTML/text in the order record (localStorage, same as the rest of the app). Commitment tab has a "Save Version to Attachments" control that snapshots the currently-generated Commitment doc, frozen at that moment. Attachments tab lists saved versions (docType, version label, date, notes) with expand/collapse "View snapshot," plus edit (label/date/notes only) and delete. CD isn't built yet, so only Commitment has a working hook right now; the data model is generic enough to add a CD hook later.
- All three toolbar sections use the same add / edit (pencil icon, inline form) / delete pattern established for Prelim Search entries.
- Vertical nav grouped under headers: **General** (Order Entry, Order Info, Contacts, Property), **Title** (Title Insurance Premiums [placeholder], Prelim Title Search, Commitment Sch A, Commitment Sch B-I/B-II, Endorsements [placeholder], Curative), and **Document Preparation** (Deed, Security Instrument, Affidavits, Power of Attorney, Notary Acknowledgement — its own flat top-level group, not nested under Title or Closing; see [[Design Notes - Platform]] for the Doc Prep design). Premiums/Endorsements are empty "coming soon" placeholders.
- File History is a 4th toolbar item: newest-first audit log per order (field old→new, add/delete events, milestones incl. Title Status changes), all timestamped. A generic helper infers field label/section for most simple fields with no per-field code; logs on "change" not "input" (no keystroke spam). Structured records get per-field diffing on Save plus single add/delete events. Contacts are deliberately scoped to one consolidated "edited" event, not full field diffing. No cross-file rollup/search yet, flat list only.
- Property Screen is nested sub-tabs within one File Section: Identification (House Number, Street Name, Suffix, Directional, City, County, State, Zip, Section/Township/Range, Brief Legal, Block/Lot, Use Type), Legal Description (Full Legal Description, Parcel Number, read-only pulled Derivation Clause), Plat/Survey Matters (a minimal placeholder — single Plat/Survey Reference field pending more detail). City/County/State/Zip/Parcel Number pre-fill once from Order Entry (non-destructive fill-if-blank — a manual edit is never overwritten by a later Order Entry change). House Number/Street/Suffix/Directional are NOT auto-parsed from Order Entry's free-text Property Address — left blank for manual entry, parsing would be fragile. Section/Township/Range are reference-only for now. The Commitment/CTC Legal Description line auto-appends "However by showing this, no additional coverage is provided" whenever a Legal Description is on file.

## Order Entry

- Screen is role-scoped/minimal (parties, property, settlement type, template); downstream data added as the file progresses. Minimum fields to open: Property, Transaction Type, Buyer/Borrower, Seller (+ Lender for Refi). No blocking gates. Auto-searches duplicate/prior files (parcel, address, loan #, party names, old closed files/prior policies).
- Product Type field (Purchase/Refinance/HELOC/HELOAN/Reverse Mortgage (Refi)/Cash Purchase/Reverse Mortgage (Purchase)/Tract Search, default Purchase) plus a Policy Type field (None/Owner's/Loan/Simultaneous, default None). Policy Type drives which policy block(s) show on Schedule A (Simultaneous = issuing both an Owner's and a Loan Policy) and auto-suggests each block's ALTA form only when that block's form is still blank, never overwriting a manual entry.
- Field list: Purchase Price, Loan Amount, Buyer/Borrower, Seller, List/Sell Agents, Lender, Mortgage Broker, Tax Collector(s), Recording Office, Settlement Agent, Title Company, Underwriter, Abstractor, Property Address, Parcel Number. Auto-population: Parcel from Address (soft-fail), City/State/County from Zip (dialogue if zip spans counties), Tax Collector(s)/Recording Office from address/parcel. Title Co/Settlement Agent/Underwriter set via state-keyed template (legal names/license #s vary by state).
- Local/global lookup table pattern (platform-wide): global = shared default; "pinning" = sole override mechanism; local tables self-build organically — fine for low-stakes lookups (Recording Office/Tax Collector), NOT higher-stakes curated content (R&E code library). Monthly compliance check: local vs. global exception report, Tableau drill-down.
- Tax certs: currently a 3rd-party vendor (self-issue liability not worth market rate); wants a self-issue option once the global lookup solves the friction.
- Buyer/Borrower & Seller contacts: entity-type selector (Individual/LLC/Corp/Partnership/Trust/Estate) changes contact screen fields. Lender/Mortgage Broker linkable for automated-email routing. Marketing/Referral Source is a pointer to any contact, not a functional role.
- Order Information screen (separate from Order Contacts): assigns functional roles (Title Officer, Curative Title Officer, Escrow Assistant, Escrow Officer, Closing Coordinator, Funder, Recorder) + Order Received Date + Order/Title/Escrow Status.
- Title Status and Escrow Status are independent (a file could be Escrow Only or Title Only). Order Status is separate — file-level retention/audit tracking.
- Status lists (final): Order Status = In Progress, Canceled, Retain, Hold, Completed, Duplicate. Title Status = In Progress, Searching, Exam, Curative, Cleared for Policy, Policy Issued, Policy Remitted, Hold - Title Only. Escrow Status = In Progress, Balancing, Docs Out, Canceled, Closed (funds disbursed). Order Status Completed is the true terminal state. Duplicate is its own status (sibling to Canceled); canceling marks all tasks N/A, no separate void/delete.
- Order Linking for multi-property package deals — full mechanics documented under Search & Exam below.
- No generic Rush flag — urgency is expressed via the real Settlement Date/task due dates.
- Scan/OCR intake at Order Entry: captures deal terms (survey, home warranty payer, seller concessions), runs compliance checks (agency named settlement agent, all sellers/spouses signed contract). Missing-signature findings report as a Requirement on the Commitment.
- Milestone/Title Status triggers, all artifact-saved events: Order Entry (until search ordered) → Searching (until search saved) → Typing and Exam (until final commitment saved) → Curative (until Title Clear to Close saved) → Cleared for Policy (until policy issued).

## Document lifecycle

- Draft/Final for Title docs (Commitment, Policy); Preliminary/Final for Escrow docs (CD). "Refresh Required" tag when underlying data changes post-generation. Draft freely refreshes; once shared/merged, Preliminary CD freezes immutable (later changes = new Preliminary version, not an in-place edit). Final adds edit-lock: CD editable only by Escrow Officer+downstream after Final; Commitment editable by Title Officer (whole doc) or Curative Title Officer (Requirements only) after Final — enforced via permissions.
- CTC: generated doc, no Draft/Final toggle, has an Issued/Rescind toggle (rescind if underlying facts materially change post-issuance). Toggling Rescind reverts Title Status to Curative.
- Rate table: locks on the first-rate-generation event (audit-trail-logged), not a fixed date — typically at/around Commitment Effective Date. Open files keep their rate table; new files get the current table; a file's assigned table can float until Exam first generates the rate.
- Commitment Finalize is reversible ("Revert to Draft," confirm-strip pattern mirroring Finalize): re-enables outright delete on Requirements/Exceptions, reverts Title Status Curative→Exam. Blocked while a CTC is issued (must Rescind first, since CTC assumes a Final Commitment). Existing Curative dispositions/Don't-Show flags are preserved through a revert, not cleared.

## Search & Typing/Exam

- Abstractor assignment depends on Product Type + State + County + Transaction Type; the system auto-sets Abstractor and fires the search request automatically on Order Entry save/close.
- Search intake tiers: (1) Live API integration (X1 Xpress/Westcor, iDX/Fidelity, DataTrace) — real-time. (2) PXT/structured file import — same trust, batch. (3) OCR/AI-assisted typing — human reviews before commit. (4) Full manual typing. A Search Order Form (doc + email) is sent to the abstractor, varying by State + Transaction Type.
- Universal Data Review Screen for ANY imported/inferred data source (PXT, OCR/AI, property copy-forward, Search Package, Date Down, lender-CD OCR): split screen, current state (left) vs. proposed post-import state (right), editable before commit. Fuzzy-matches existing contacts. Actions: Accept, Redirect, Merge, Omit. No auto-default winner on conflicts.
- Imported search data does NOT write directly to Requirements/Exceptions — it populates the "Preliminary Title Search and Opinion" staging screen. The examiner selects R&E codes onto the Commitment; codes pull supporting detail from staging data.
- R&E code library varies by Underwriter AND State AND County/City. Global tier curated/sourced directly from the underwriter (E&O risk) with hierarchy-fallback (state, overridden by county, then city). Local/pinned customizations stay strictly local, no promotion to global.
- Exam's three screens: (1) **Property** — Address/City-Muni/County/State, Brief Legal, Block/Lot, Legal Description, Plat/Survey, CCRs/Master Deed, Access/Easements/ROW, Use Type (stable, copy-forward safe). (2) **Commitment Screen** — Premiums, Endorsements, Sch A (Chain of Title), Sch B-I (Requirements)/B-II (Exceptions) [Texas: A/B (Exceptions)/C (Requirements)/D (Disclosures), the only non-ALTA state]. (3) **Prelim Title Search & Opinion** — Search Period/Type/Length, Effective Date, Derivation, Mortgages/Deeds of Trust, Other Liens/Encumbrances, Notices of Commencement. Property = canonical facts feeding Sch A; Prelim = raw findings feeding B-I/B-II via R&E codes; Commitment Screen = assembled output.
- Commitment's Sch B-I/B-II offer "From this file" requirement/exception chips generated from Prelim data, alongside generic boilerplate chips: each Security Instrument/Lien produces a Release/Satisfaction requirement (parties, dated/recorded date, book/page/instrument no., amount); each Exception Matter produces its B-II exception language. Clicking pushes a fully-formed, still-editable string and tags the record with sourceType+sourceId so its chip disappears once used, reappears if deleted. Requirements/Exceptions are editable in place (pencil icon, inline form). Related Documents attached to a Security Instrument (Assignment, Assignment of Leases and Rents, Assignment of Beneficial Interest, Loan Modification Agreement, Substitution of Trustee, UCC Addendum - Continuation, Other) generate their own sub-item requirement chips, gated on the parent SI's own requirement already being added; numbered as sub-items of the parent (1a, 1b under parent "1") via a parentReqId link + array-contiguity-based labeling. No type-based exclusions — full detail in [[Design Notes - Curative & Tasking]].
- Schedule A is its own File Section tab (Prelim Search → Commitment): Date/Time Issued, Title Held As, Countersignature, read-only Effective Date. Policy/coverage splits per Order Entry's Policy Type: Owner's Policy card (ALTA Form, Proposed Insured w/ per-contact + grouped "All Buyer/Borrowers" chips, Coverage Amount) for Owner's/Simultaneous; Loan Policy card (ALTA Form, Proposed Insured w/ Lender chips, Mortgagee Clause textarea, Coverage Amount) for Loan/Simultaneous; Simultaneous shows both; None shows neither. Loan Policy's Mortgagee Clause chip composes Lender Name + Address directly from the Lender contact by default; the Lender contact's own Mortgagee Clause field is an explicit override, used instead only if filled. Chain of Title is its own independent multi-entry list (Instrument Type, Grantor, Grantee, Dated/Recorded Date, Book, Page, Instrument #) with a "Copy from Derivation" seed chip. Coverage Amount defaults from Order Entry (Purchase Price→Owner's Policy, Loan Amount→Loan Policy), same non-destructive fill-if-blank pattern used elsewhere — never overwrites a value already typed, and a later Order Entry change doesn't retroactively update an already-filled Coverage Amount.
- Wants a Requirement Code Library and a separate Exception Code Library (lookup tables) — not yet built. Requirements/Exceptions stay free-text-with-notes for now.
- Prelim Search screen: Search From date has no time (only Effective Date/Time and Search To Date/Time do); Search Type is free-text. Three staging categories: **Security Instruments** (Instrument Type: Mortgage/Deed of Trust/Security Deed/UCC Financing Statement; Dated/Recorded Date, Mortgagor, Mortgagee, Trustee, Consideration, Book, Page, Instrument #; nested Related Documents list per instrument), **Liens & Encumbrances** with per-Type field sets (Judgment, Tax Lien, HOA/COA Lien, Mechanics Lien, Lis Pendens, Tax Sale Certificate, legacy Municipal/Utility Lien) — selecting a Type live-reshapes the field grid pre-Save, non-destructively, **Exception Matters** — catch-all B-II matters not tied to a recorded instrument (easements/restrictive covenants/ROW). All list records here (plus Derivation Vesting Principals) are pencil-icon inline-editable.
- Derivation (current vesting) is a structured record: Instrument Type (17-value dropdown), Dated/Recorded Date, Book, Page, Instrument Number, Consideration, Grantor/Grantee (Grantee = current owner) + Entity Type, plus a Trustee/Member-Manager roster for Trust/LLC/Corp/Partnership — independent from a Contact's principals since vesting-deed parties can differ from today's signers. Grantee auto-fills from Contacts by Transaction Type when unambiguous; "Copy from a file contact" pre-fills name/entityType/principals, editable after. Married-couple handling: grouping over merging (preserves per-person data used elsewhere — signature lines/SSN/DOB/POA/History). When candidates are exactly 2 people married to each other, Grantee auto-fills "X and Y, husband and wife"; 3+ candidates still bail (won't drop a co-owner). Grantor mirrors Grantee — own Entity Type + roster + "Copy Grantor from a file contact" (any contact) — both render entity-qualified in the clause.
- Derivation Clause: "Being the same parcel conveyed unto GRANTEE by INSTRUMENT TYPE of GRANTOR recorded RECORDED DATE as Book/Page and/or Instrument No. of the COUNTY County records" (County from Property → Identification) — distinct from "Vested In" (vesting naming), shown separately in multiple places. Parcel/portion lead-in is an either/or checkbox (default = same parcel), not fixed text.
- Every persisted list-type record has pencil-icon inline edit (audited across the whole prototype). Two deliberate exceptions: Contacts use a different, already-complete edit path (click the row to open the full-screen Contact editor); the in-progress Principals list inside an unsaved Add/Entity-Contact draft form stays remove-and-re-add only (ephemeral staging, not a persisted record).
- Order Linking: one parent + linked sub-orders, flat hierarchy only. "+ Add Linked Property" (parent-only) one-time-copies Transaction Type, Settlement Date/Time, Vesting, Functional Roles, deep-cloned Contacts — NOT inherited: Property, Prelim Search, Commitment, Tasks, Attachments, File No., Status (independent per file). Sub-order shows a "part of a package" banner; siblings listed/clickable both directions. Deleting a parent doesn't cascade-delete children.
- Texas Schedule D is fixed boilerplate: discloses the T00 abstractor search fee (TDI requires it paid from the agent's premium portion); Fee/Payee/Purpose auto-populate from the Abstractor assignment.
- Premiums/Endorsements/CPL fee/UW split auto-populate from the rate table but the examiner reviews/confirms/can override. Lender-as-first-class-entity idea tabled for a future "VIP Client Management" feature area.
- Property "title plant" copy-forward: a prior-file match pulls Property Screen data directly from that prior file (file-to-file, not a warehouse), routed through the Data Review Screen. Multiple prior files: most recent is default/primary, older disagreeing fields red-flagged (not a full N-way merge).

## Contact address model

- Buyer/Borrower and Seller contacts carry Current Address, Mailing Address, and Forwarding Address as three distinct fields, plus Phone, Email, and (Individual entity type only) SSN and Date of Birth. Lender contacts carry a single Address field plus an optional Mortgagee Clause override.
- Occupancy Type lives on the Order Contact (Buyer/Borrower), not the Property Screen — avoids the title-plant copy-forward problem. Use Type stays on the Property Screen (a stable characteristic).
